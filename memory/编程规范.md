## 一、铁律（绝对禁止）

### 铁律1：交易数据绝不编造
所有交易相关数据（行情/K线/板块/财务等）必须来自真实数据源，禁止伪造。

### 铁律2：K线禁止以数组位置取价格
禁止用 `data[0]` 或 `data[-1]` 取价格，必须以 `time`/`date` 字段为准：
```python
# ❌ 错误
price = data[-1]['close']

# ✅ 正确
latest_record = max(data, key=lambda x: x['date'])
price = latest_record['close']
```

### 铁律3：本地数据路径必须正确
```
中间过程/klines/SPY_1d.json  → 1601天 ✅（正确路径）
fintech/p1/klines/SPY_1d.json → 502天  ❌（旧路径，废弃）
```

## 二、数据采集核心原则

### 原则1：获取数据前必须先检查本地现状
```
每次任务前必须执行：
1. 确认今日日期
2. 确认本地文件最新日期（遍历找 max date）
3. 以两者差值决定是否需要拉取新数据
```
禁止：不查本地文件就直接调用 API。

### 原则2：HTTP 200 ≠ 数据成功（快速失败核心）
请求成功只是"连接通了"，必须验证返回的数据是否符合业务预期：
```python
# 必须验证
assert len(timestamps) > 0, "timestamp 为空"
assert len(data) >= expected_min, f"数据量异常: {len(data)} < {expected_min}"
assert not error_in_response, f"API error: {error}"
```

### 原则3：多数据源优先级（失败立即切换）
| 优先级 | 数据源 | 方法 |
|--------|--------|------|
| ① | Yahoo Finance (`yfinance`) | Python 包，有频率限制 |
| ② | Yahoo Browser JS Fetch | 通过 Chrome CDP 执行 JS（绕过限速首选）|
| ③ | Yahoo 网页 | Playwright CDP，需等待 JS 渲染 |

## 三、快速失败原则

### 技术层失败（可重试1-2次）
| 场景 | 处理 |
|------|------|
| 网络超时 | 重试1-2次，加退避 |
| HTTP 5xx | 重试1次 |
| 连接被拒绝 | 立即退出，不重试 |
| JSON解析失败 | 立即退出，不重试 |

### 业务层失败（0次重试，立即失败）
| 场景 | 处理 |
|------|------|
| 空数据 | 立即失败 |
| 数据不足 | 立即失败 |
| error 字段存在 | 立即失败 |
| 字段缺失 | 立即失败 |

### 重试策略表
| 错误类型 | 可重试？ | 次数 |
|----------|---------|------|
| 网络超时 | ✅ | 1-2次 |
| HTTP 5xx | ✅ | 1次 |
| HTTP 4xx | ❌ | 0次 |
| JSON解析失败 | ❌ | 0次 |
| 空数据/数据不足 | ❌ | 0次 |

## 四、新需求验证：小 Demo 优先原则

### 触发场景
引入新的 API、新的数据源、新的策略逻辑、或对现有流程做重大修改时。

### 标准验证流程
```
第一步：选定 1-3 只代表性股票（SPY + AAPL + 低流动性股票）
第二步：单次请求测试 → 验证数据量/字段/日期范围
第三步：连续 3-5 次请求测试 → 验证去重/追加逻辑
第四步：确认OK后再全量
```

### 快速验证模板
```python
def quick_verify(symbols, interval):
    results = {}
    for sym in symbols:
        try:
            data = fetch_one(sym, interval)
            assert len(data) > 0, f"{sym}: 空数据"
            assert 'close' in data[0], f"{sym}: 字段缺失"
            results[sym] = "OK"
        except Exception as e:
            results[sym] = f"FAIL: {e}"
    return results

print(quick_verify(['SPY', 'AAPL', 'MSFT'], '1h'))
```

## 五、后台运行 + 最高权限停止原则

### 为什么必须在后台
1. 用户可随时干预：发现问题 → 喊停 → 立即响应
2. 不阻塞主对话
3. 方便监控进度
4. 便于紧急 kill

### 操作规范
```
启动：background=true
监控：process poll/log
停止：kill -9 <pid>（SIGKILL，不可捕获）
```

### 停止检查清单
1. kill 所有相关进程（fetch_us_stocks / playwright / chromium）
2. 确认 Chrome CDP 端口无残留连接
3. 确认进程已完全退出
4. 报告已停止

## 九、增量更新原则

- 脚本必须幂等：重复运行不会重复拉数据，不会破坏已有数据
- 增量逻辑：读取本地最新日期 → 判断是否需要补数据 → 追加写入
- 全量逻辑（`--full`）：删除所有文件后重新下载
